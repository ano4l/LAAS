## 1. Player rating / ranking: which open methods and code exist, and which can a prototype reuse?

### Takeaway
The directly reusable, actively maintained open code is `socceraction` (MIT; SPADL + VAEP + xT) and `mplsoccer` (MIT; pitch/radar/pizza plotting); percentile ranks, weighted z-score composites and cosine-similarity search are simple enough that open projects implement them ad hoc rather than as a library. PlayeRank has public code but no licence file, and plus-minus and "player vectors" are published methods without an official open implementation.

### Cited Findings
- `socceraction` — "Convert soccer event stream data to SPADL and value player actions using VAEP or xT"; licence MIT; last push 2026-10-18; not archived; 829 stars (GitHub API, 2026-11-18). Inputs: event-stream data converted to SPADL. — [ML-KULeuven/socceraction](https://github.com/ML-KULeuven/socceraction)
- `mplsoccer` — "Football pitch plotting library for matplotlib"; licence MIT; last push 2026-10-27; not archived; 555 stars (GitHub API, 2026-11-18). — [andrewRowlinson/mplsoccer](https://github.com/andrewRowlinson/mplsoccer)
- PlayeRank (Pappalardo et al., ACM TIST 2019): code is public at mesosbrodleto/playerank. The repo page shows no LICENSE file and no licence statement; README asks users to cite the 2019 paper. Inputs: "soccer-logs" where each match is a sequence of events (player id, event type, position, timestamp). Four steps: (1) compute feature weights (learning), (2) compute roles (learning), (3) compute performance scores (rating), (4) aggregate scores (ranking). A Google Colab reproduction tutorial is provided. — [mesosbrodleto/playerank](https://github.com/mesosbrodleto/playerank)
- PlayeRank repo had about 85 stars and was last updated November 2023 according to a third-party index. — [relatedrepos.com](https://relatedrepos.com/gh/mesosbrodleto/playerank)
- PlayeRank paper preprint. — [arXiv 1802.04987](https://arxiv.org/abs/1802.04987v3); pre-computed PlayeRank scores (playerank.json, 5.95 MB) are on figshare, credited to Pappalardo and Cintia. — [figshare PlayeRanks](https://figshare.com/articles/PlayeRanks/9361148)
- A 2024 preprint, "Revisiting PlayeRank" (Schmidt, Lillo, Bustos), revises the original method. — [arXiv 2410.20038](https://arxiv.org/abs/2410.20038v1)
- Player Vectors (Decroos & Davis, ECML PKDD 2019): playing style defined as where on the pitch a player tends to perform specific on-ball actions; method filters event types, builds zone-based heatmap features, compresses with non-negative matrix factorisation, and concatenates per-action-type vectors into a fixed-length player vector. — [mlanthology entry](https://mlanthology.org/ecmlpkdd/2019/decroos2019ecmlpkdd-player); [Springer](https://link.springer.com/10.1007/978-3-030-46133-1_34)
- Only an unofficial Python implementation of Player Vectors was found (raphaelsenn/playervectors, plus a companion repo for clustering / position prediction from the vectors); no official author code release was found. — [ecosyste.ms index of raphaelsenn/playervectors](https://awesome.ecosyste.ms/projects/github.com%2Fraphaelsenn%2Fplayervectors)
- Plus-minus: Kharrat, McHale & López Peña, "Plus–minus player ratings for soccer", European Journal of Operational Research 2020, 283(2):726–736 — adapts basketball/ice-hockey plus-minus and proposes two new variations. — [RePEc](https://econpapers.repec.org/RePEc:eee:ejores:v:283:y:2020:i:2:p:726-736); accepted manuscript at [Liverpool repository](https://livrepository.liverpool.ac.uk/id/eprint/3063562)
- Hvattum (2020) proposes separate offensive and defensive plus-minus ratings; Hvattum (2019) is a comprehensive review of plus-minus ratings in team sports (Int. J. Computer Science in Sport). — [Hvattum 2020 PDF](https://himolde.brage.unit.no/himolde-xmlui/bitstream/11250/3031900/1/Hvattum.%2b2020.%2bOffensive%2band%2bdefensive%2bplus-minus%2bplayer%2bratings%2bfor%2bsoccer%2b%2528AS%2529.pdf); [Hvattum 2019 review](https://reference-global.com/article/10.2478/ijcss-2019-0001)
- A 2024 preprint proposes regularised adjusted plus-minus models "for evaluating and scouting" football players using possession sequences. — [arXiv 2407.17832](https://arxiv.org/html/2407.17832v2)
- No published open-source code repository was found for the Kharrat et al. or Hvattum plus-minus models. — [search of record: RePEc entry](https://econpapers.repec.org/RePEc:eee:ejores:v:283:y:2020:i:2:p:726-736)
- The Soccermatics course (readthedocs) includes a scouting lesson with a page on plus-minus as "Other approaches to scouting", and a Streamlit lesson. Course repo is MIT-licensed, last push 2026-01-13 (GitHub API, 2026-11-18). — [Soccermatics PlusMinus page](https://soccermatics.readthedocs.io/en/latest/lesson3/PlusMinus.html); [Soccermatics Streamlit lesson](https://soccermatics.readthedocs.io/en/latest/lesson10/Streamlit.html); [soccermatics/Soccermatics](https://github.com/soccermatics/Soccermatics)
- `griffisben/Soccer-Analyses` — author's code to build datasets "from FBRef" and visualisations (percentile/scouting-style work); MIT; last push 2024-03-19; 154 stars (GitHub API, 2026-11-18). Its FBref-dependent parts are affected by the January 2026 FBref data loss (see section 4). — [griffisben/Soccer-Analyses](https://github.com/griffisben/Soccer-Analyses)
- `devinpleuler/analytics-handbook` — "Getting started with soccer analytics"; MIT; last push 2024-05-26; 1,718 stars (GitHub API, 2026-11-18). — [devinpleuler/analytics-handbook](https://github.com/devinpleuler/analytics-handbook)
- `eddwebster/football_analytics` (2,862 stars, last push 2025-10-09) and `mckayjohns/youtube-videos` (153 stars, last push 2025-07-10) have NO licence file (GitHub API, 2026-11-18) — usable as reading material, not as code to copy into a product. — [eddwebster/football_analytics](https://github.com/eddwebster/football_analytics); [mckayjohns/youtube-videos](https://github.com/mckayjohns/youtube-videos)
- `ML-KULeuven/un-xPass` ("Measuring soccer player's creativity") — licence unclassified (`NOASSERTION`), last push 2024-07-17 (GitHub API, 2026-11-18). — [ML-KULeuven/un-xPass](https://github.com/ML-KULeuven/un-xPass)
- Elo-style open source of team strength: `soccerdata` lists Club Elo among its supported sources. — [probberechts/soccerdata](https://github.com/probberechts/soccerdata)

### Inferences
- A prototype can honestly "genuinely calculate" rankings with three layers, all implementable on open event data: (a) per-90 and possession-adjusted aggregates with a minimum-minutes filter, converted to percentile ranks within position group (no library needed; plain pandas/SQL); (b) a user-weighted composite = weighted sum of z-scored or min-max-scaled metrics, with weights stored per ranking template; (c) action-value ratings via `socceraction` (VAEP/xT), which is MIT and current.
- PlayeRank should be treated as a published method to re-implement (or to ask the authors for a licence), not as code to embed, because the repository has no licence.
- Player similarity (cosine or Mahalanobis on standardised per-90 profiles; PCA/UMAP for display; k-means/GMM for role clusters) has no dominant library; community Streamlit apps implement cosine similarity directly (see section 2). The Player Vectors method (NMF over action heatmaps) is the main published role/style-detection approach from event locations and is straightforward to re-implement with scikit-learn.
- Background knowledge, not verified this session: mplsoccer provides `Radar` and `PyPizza` classes used for FBref/StatsBomb-style percentile "pizza" charts; socceraction ships SPADL converters for StatsBomb, Wyscout and Opta formats plus an "atomic" VAEP variant. A React front end would need to draw its own charts (mplsoccer is matplotlib-only, so it is useful server-side or as a reference design).

### Gaps
- No open equivalent of SciSports' "SciSkill" was found; no source describing an open SciSkill-like implementation was retrieved. The nearest open ingredients are Club Elo team ratings and plus-minus papers.
- mplsoccer's pizza/radar API and socceraction's converter list were not re-fetched from the docs this session.
- Possession-adjustment formulas (e.g. StatsBomb's sigmoid PAdj) were not sourced this session.
- Validation evidence for VAEP/xT/PlayeRank beyond the original papers (e.g. agreement with expert rankings, market value) was not retrieved, except that "Revisiting PlayeRank" (2024) exists as a critical revision.
- Licence text of un-xPass, and of the unofficial playervectors repo, not confirmed.

## 2. Recruitment-suitability and "explained" recommendations: open or published approaches and open scouting tools

### Takeaway
No standard open library produces explainable recruitment-fit scores; what exists is a pattern (role template = weighted KPIs + percentile/similarity to a target profile, adjusted for league strength and age) implemented in small community Streamlit apps whose licences are mostly unstated or non-commercial. Published age-curve studies and open league-strength proxies (Club Elo league averages) provide defensible adjustment inputs.

### Cited Findings
- Community scouting apps found (licences NOT confirmed unless stated; several were surfaced only through GitHub mirror domains and must be checked on github.com):
  - MJenius/Scouting-Dashboard — scouting decision-support tool with a Streamlit front end and a FastAPI back end; similarity engine uses cosine similarity with extra weighting on traits above the 75th percentile. — [mirror of MJenius/Scouting-Dashboard](https://github.153394839.workers.dev/MJenius/Scouting-Dashboard)
  - alexgasconn/player-recommender — Streamlit app on FBref data; distances normalised to 0–100% similarity; top-10 closest players; radar charts. — [write-up](https://blog.gopenai.com/finding-statistically-similar-footballers-with-pca-and-clustering-039aa14fa198)
  - MS3B09/Botola-Scout — Streamlit scouting app for the Moroccan league (an African-league precedent). — [mirror of MS3B09/Botola-Scout](https://github.imc.re/MS3B09/Botola-Scout)
  - LaErre9/Player_Scouting_Recommendation_System — similarity features; licence is CC BY-NC 4.0 (non-commercial, so not reusable in a commercial club product). — [mirror of LaErre9/Player_Scouting_Recommendation_System](https://github-users.yhajoa.workers.dev/LaErre9/Player_Scouting_Recommendation_System)
- Soccermatics course materials (MIT repo) cover scouting and building a Streamlit app. — [Soccermatics Streamlit lesson](https://soccermatics.readthedocs.io/en/latest/lesson10/Streamlit.html); [soccermatics/Soccermatics](https://github.com/soccermatics/Soccermatics)
- League strength (open proxy): ClubElo provides Elo ratings for thousands of clubs along with a league average, which one analyst used to adjust for league-strength differences. — [statsultra.com](https://statsultra.com/football-club-strength-ratings/)
- League strength (published but not open data): Opta Power Rankings measure league strength by averaging team ratings within a league; no free API was found. — [The Analyst](https://theanalyst.com/articles/strongest-football-leagues-in-the-world-opta-power-rankings)
- League strength (method paper): Glicko-2-based ratings of European and South American leagues; its data came from Flashscore (terms would need checking before reuse). — [arXiv 2310.11459](https://arxiv.org/html/2310.11459v1)
- Age curves: Dendir, "When do soccer players peak? A note" (Journal of Sports Analytics, 2017) — average professional peaks between 25 and 27; average forward at 25, typical defender at 27; midfielders within the 25–27 band depending on model; data from four major European leagues 2010–2015; goalkeepers excluded; peak age may vary with ability. — [record](https://lida.sport-iat.de/dfb/Record/4045076?lng=en); [Radford University release](https://www.radford.edu/content/radfordcore/home/news/releases/2016/october/at-what-age-do-soccer-players-peak--ask-an-economist.html)
- Age curves: a 2019 Frontiers in Psychology study of Champions League players found goalkeepers and centre-backs tend to peak later than attackers, with peak performance lasting until about 31. — [Frontiers 2019](https://www.frontiersin.org/articles/10.3389/fpsyg.2019.00076/full)
- Age curves in lower-ranked leagues are described as fairly unexplored by a Linköping University group paper on peak age by position. — [Säfvenberg et al. PDF](https://www.ida.liu.se/~nikca89/papers/isace24.pdf)
- Hudl has a public article on finding similar players (content not read). — [Hudl blog](https://www.hudl.com/blog/finding-similar-players)

### Inferences
- An honest "explained suitability" output can be built without ML: for a chosen role template, show each KPI's percentile vs positional peers, the weight applied, each KPI's contribution to the total, the sample (minutes, matches, competition), a league-strength note, and an age-band note. That is fully transparent and avoids needing SHAP. SHAP becomes relevant only if a fitted model (e.g. VAEP's gradient-boosted classifier, or a custom success model) is used.
- All published age-curve evidence found is from European top leagues or the Champions League; applying a 25–27 peak band to the South African Premiership is an extrapolation and should be labelled as such.
- Club Elo coverage is Europe-centred (background knowledge, not verified this session); for South African and CAF competitions a league-strength coefficient would have to be estimated or sourced commercially (e.g. Opta Power Rankings), and the UI should say so.

### Gaps
- No football-specific open implementation or peer-reviewed paper on SHAP-explained recruitment-fit scores was retrieved this session.
- Licences of MJenius/Scouting-Dashboard, alexgasconn/player-recommender, MS3B09/Botola-Scout and KikeRev/smart_scout_app not confirmed (search results did not show them; GitHub API rate limit prevented checks).
- Friends of Tracking repositories (SoccermaticsForPython, LaurieOnTracking) and McKay Johns' materials: licences for the FoT repos could not be checked (API rate limit); McKay Johns' youtube-videos repo has no licence (confirmed).
- No open league-quality coefficient covering South African competitions was found.
- "Video evidence" linkage for shortlists (event → clip timestamp) has no open standard found in this research; StatsBomb/Wyscout open events carry timestamps but no open video.

## 3. Development and retention: published methods, open Transfermarkt data, evidence fields

### Takeaway
The only large open-licensed source of market values, appearances/minutes and transfers is `dcaribou/transfermarkt-datasets` (repository CC0-1.0), but its updates are paused (current to 6 July 2026) and the legality of the underlying scrape under Transfermarkt's own terms was not confirmed. Development tracking itself rests on published age-curve work plus simple rolling-form and availability calculations.

### Cited Findings
- `dcaribou/transfermarkt-datasets` — licence CC0-1.0; last push 2026-09-05; not archived; 529 stars (GitHub API, 2026-11-18). — [dcaribou/transfermarkt-datasets](https://github.com/dcaribou/transfermarkt-datasets)
- Its README lists 12 tables: competitions (65), clubs (790+), players (50,000+), games (88,000+), appearances (1,890,000+), player_valuations (650,000+), club_games (177,000+), game_events (1,270,000+), game_lineups (3,170,000+), transfers (175,000+), countries (124), national_teams (124). Published as zip, DuckDB file and gzipped CSVs, and on Kaggle as davidcariboo/player-scores. — [dcaribou/transfermarkt-datasets](https://github.com/dcaribou/transfermarkt-datasets)
- Status notice in the README: "Updates are paused. The dataset is current to 6 July 2026." The pipeline stopped completing in mid-July 2026 with no estimated resumption; `games` has nothing after 2026-07-06, `appearances` after 2026-06-28, `player_valuations` after 2026-06-12; 2026/27 squads are not covered. — [dcaribou/transfermarkt-datasets](https://github.com/dcaribou/transfermarkt-datasets)
- The README makes no statement about the legality or terms of scraping Transfermarkt; it names Transfermarkt as the source. National-team tournaments listed include AFCON; the page does not confirm whether South African club competitions are among the 65 competitions. — [dcaribou/transfermarkt-datasets](https://github.com/dcaribou/transfermarkt-datasets)
- A third-party listing of a Kaggle Transfermarkt dataset shows licence "Other" (may be a different upload), i.e. licence labelling is inconsistent across mirrors. — [hyper.ai listing](https://hyper.ai/en/datasets/50867)
- General legal caution (from the soccerdata project FAQ): the EU sui generis database right protects database contents; scraping can be legally risky, especially when data is reused or republished; breaching a website's terms of use is a separate risk. — [soccerdata FAQ](https://soccerdata.readthedocs.io/en/stable/_sources/faq.rst.txt)
- `JaseZiv/worldfootballR` (R wrapper for FBref, Transfermarkt, Understat) is archived; last push 2025-09-18; no licence detected (GitHub API, 2026-11-18). — [JaseZiv/worldfootballR](https://github.com/JaseZiv/worldfootballR)
- Age-curve evidence for development/peak-age charts: see Dendir (peak 25–27; forwards 25, defenders 27) and the 2019 Champions League study (GK/CB later, to about 31). — [Dendir record](https://lida.sport-iat.de/dfb/Record/4045076?lng=en); [Frontiers 2019](https://www.frontiersin.org/articles/10.3389/fpsyg.2019.00076/full)

### Inferences
- A CC0 label on the repository covers the maintainer's own contribution; it cannot grant rights the maintainer does not hold over Transfermarkt's content. For a commercial club product, Transfermarkt-derived market values should be shown, if at all, as clearly attributed third-party estimates in a demo, with a legal check before production use.
- Evidence fields an analyst-facing retention summary can reasonably show, all computable from open or club-owned data: age and position-specific age band (with the "European-data" caveat); minutes share and availability (matches in squad / started / completed, days unavailable); rolling form (e.g. rolling 5–10 match per-90 or VAEP) versus season baseline; rank and percentile within squad and within position in the competition; trend direction with sample size; role depth chart (who else covers the role); contract end date and squad status (club-entered); market-value history if licensed. The summary should list evidence for and against and leave the decision to staff — consistent with the brief's "evidence for an analyst, not an automated decision".
- Squad age-profile ("peak age") charts need only date of birth and minutes; the shaded peak band should be configurable per position rather than hard-coded.

### Gaps
- Transfermarkt's current terms of use (scraping / automated access / reuse clauses) were not retrieved; no primary source confirmed.
- No peer-reviewed open contract-value or retention-decision model was retrieved this session.
- Whether dcaribou's dataset includes the South African Premiership was not confirmed.
- The Kaggle licence field for davidcariboo/player-scores was not read directly.

## 4. Open player-statistics data (and commercial fallbacks for South African football)

### Takeaway
There is no open event or player-statistics dataset for South African club competitions; the closest open African data is StatsBomb's free AFCON 2023 release (52 matches). For South African leagues the confirmed commercial route is Hudl/Wyscout, which signed a rights collaboration with the PSL covering the Premiership, Championship and DStv Diski Challenge for 2024-25 and 2025-26. FBref lost its Opta-supplied advanced statistics on 20 January 2026 and is no longer a source of progressive-pass or xG data.

### Cited Findings

### Inferences
- For an honest demonstration of scouting metrics (progressive passes, xT/VAEP, position rankings), StatsBomb open data is the best base because it is current, well documented and includes an African competition (AFCON 2023, with South Africa's national team participating — background knowledge that South Africa finished third; not verified this session). The dashboard must show StatsBomb attribution and logo and label the data as demonstration data, not club data.

## 5. GPS workload: vendor export formats, open parsers, standard external-load metrics and thresholds

### Takeaway
There is no open, vendor-neutral Python parser for Catapult or STATSports exports; the practical approach is a small configurable CSV importer plus Catapult's own R client (`catapultR`) or OpenField Cloud API where the club has access. The widely used absolute thresholds (high-speed running >19.8 km/h, sprinting >25.2 km/h, accelerations/decelerations beyond ±3 m/s², 10 Hz GPS) are conventions without physiological basis or consensus, so thresholds must be configurable and displayed.

### Cited Findings
Vendor formats and tools
- Catapult: `catapultR` is an R package giving access to Catapult data via wrapper functions around OpenField Cloud API queries; installed from GitHub (`SBGSports/catapultr`); authentication uses an API token created in OpenField Cloud settings, enabled on the account by a Catapult customer-success representative; the package is copyrighted by Catapult Sports; docs list version 0.0.0.61 as of 10 March 2025 and advise processing in small batches to avoid stressing the cloud. — [catapultR site](https://catapultr.catapultsports.com/); [installation and login](https://catapultr.catapultsports.com/installation_demo.html)
- `SBGSports/catapultr` on GitHub: licence unclassified (`NOASSERTION`), last push 2026-11-18, 4 stars (GitHub API, 2026-11-18) — maintained by the vendor, not a permissive open-source licence. — [SBGSports/catapultr](https://github.com/SBGSports/catapultr)
- Catapult publishes a support article on exporting 10 Hz sensor data from the OpenField Console (page blocked to the fetch tool; column list not verified). — [Catapult support](https://support.catapultsports.com/hc/en-us/articles/360001427755-Exporting-10Hz-Sensor-Data-from-the-OpenField-Console)
- STATSports: raw export path in Sonra is Export Data → Raw Data → Raw Data Extended (per practitioner guides); Sonra also offers event-level CSV exports (each sprint, high-metabolic-load efforts, high-intensity bursts). — [practitioner guide](https://emcgleenan23.github.io/pfv-practitioners-guide.html); [STATSports metric event exports](https://statsports.com/article/sonra-metric-event-exports-applications-and-visualisations)
- A practitioner describes an open-source Python pipeline turning STATSports GPS exports into summaries (repository and licence not confirmed). — [GPS processing pipeline page](https://emcgleenan23.github.io/gps-pipeline.html)
- Real-world example of STATSports APEX raw fields (from the open SoccerMon dataset): GNSS position, speed and heart rate at 10 Hz; per-row fields time, sensor ID, heart_rate, lat, lon, speed, hacc, hdop, signal_quality, num_satellites, inst_acc_impulse, accl_x/y/z, gyro_x/y/z; stored as Parquet by team/year/month/day. The paper's text and table disagree on accelerometer rate (952 Hz vs 100 Hz). — [SoccerMon paper, PMC11139986](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11139986/)
- FIFA EPTS standard transfer format: two parts — metadata and a data-format specification, both defined in an XSD schema, delivered as an XML file, plus a raw data file that may be in any format the provider prefers (not necessarily XML). FIFA describes it as a first version to be continuously updated; language versions of the page show different "last updated" dates (1 September 2021 vs 1 April 2026). — [FIFA EPTS standard data format](https://inside.fifa.com/innovation/standards/epts/research-development-epts-standard-data-format); [standard transfer format documentation PDF](https://fifa-quality-prod-1.azurewebsites.net/media/171893/standard-transfer-format-documentation.pdf)
- EPTS raw files lack column names and use three different separators; the metadata file is needed to interpret players and fields. — [databallpy docs](https://databallpy.readthedocs.io/en/main/introduction/intro_tracking_data_page.html)
- `kloppy` — "standardizing soccer tracking- and event data"; BSD-3-Clause; last push 2026-11-06; 572 stars (GitHub API, 2026-11-18). Its Metrica module has an EPTS tracking loader taking an XML metadata file and a raw data file (function name differs between docs versions: `load_tracking_epts` vs older `load_epts_tracking_data`). — [PySport/kloppy](https://github.com/PySport/kloppy); [kloppy docs preview, Metrica provider](https://deploy-preview-546--unruffled-nobel-ed43d4.netlify.app/reference/providers/metrica)
- `floodlight` — "Python package for streamlined analysis of sports data"; MIT; last push 2026-05-04; 135 stars (GitHub API, 2026-11-18). Its io module lists parsers for dfl, kinexon, opta, secondspectrum, skillcorner, sportradar, statsbomb, statsperform, tracab, plus built-in public datasets (EIGD-H, IDSSE, StatsBomb open data, a toy dataset). No Catapult, STATSports or FIFA EPTS parser is listed. — [floodlight-sports/floodlight](https://github.com/floodlight-sports/floodlight); [floodlight io docs](https://floodlight.readthedocs.io/en/latest/modules/io/io.html)
- `databallpy` ("Load, synchronize, and Analyse your Soccer Data") exists as another Python option. — [alek050/databallpy](https://github.com/alek050/databallpy)

Metrics and thresholds
- A scoping review of adult male professional soccer found most studies used 10 Hz GPS units and absolute thresholds — high-speed running >19.8 km/h, sprinting >25.2 km/h, accelerations/decelerations beyond ±3 m/s² — and concluded monitoring remains dominated by GPS and absolute thresholds with limited individualisation. — [Frontiers in Sports and Active Living (DOI 10.3389/fspor.2025.1603767)](https://www.frontiersin.org/journals/sports-and-active-living/articles/10.3389/fspor.2025.1603767/pdf)
- A 2023 systematic review of professional adult soccer found no consensus on the absolute thresholds defining high-speed and sprint running, and suggested that until international standards exist, thresholds be set considering the range in the literature. — [PMC9968809](https://pmc.ncbi.nlm.nih.gov/articles/PMC9968809)
- One practitioner account traces 19.8 km/h (HSR) and 25.1 km/h (sprint) to a 2009 Premier League optical-tracking study, later adopted as GPS vendor defaults; note the 25.1 vs 25.2 discrepancy between sources. — [Malone, "How to Use GPS Thresholds"](https://maloneperform.substack.com/p/how-to-use-gps-thresholds)
- Individualised speed thresholds are proposed as an improvement but have significant implementation barriers (per Catapult's own article); sources note there is no physiological rationale for arbitrary fractions of peak speed. — [Catapult blog](https://www.catapult.com/blog/individualisation-gps-speed-thresholds-challenges-complexities)
- A published feature set used in research (Rossi et al. 2018): total distance, high-speed running distance, metabolic distance, high metabolic load distance (and per minute), explosive distance, accelerations/decelerations above 2 and 3 m/s², Dynamic Stress Load, Fatigue Index. — [Rossi et al., PLOS ONE](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0201264)
- GPS accuracy evidence cited by SoccerMon for STATSports APEX relies largely on an external study (about 1–2% distance bias); receiver firmware pre-filters raw GPS data. — [SoccerMon paper, PMC11139986](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11139986/)

### Inferences
- The prototype's "GPS external load" block can be computed from either (a) vendor session-summary CSVs (one row per player-session; map vendor column names to canonical fields: duration, total distance, HSR distance, sprint distance, accel/decel counts, max speed, PlayerLoad or Dynamic Stress Load) or (b) raw 10 Hz samples (integrate speed for distance; band by speed thresholds; differentiate speed for accelerations). Distance per minute = total distance / duration. Because vendor-specific composite metrics (PlayerLoad, Dynamic Stress Load, high metabolic load distance) are proprietary definitions, they should be imported and labelled by vendor rather than recomputed or compared across vendors.
- Since no consensus thresholds exist, each speed/acceleration band should be a stored, visible setting (defaults 19.8 / 25.2 km/h and ±3 m/s², with ±2 m/s² as a common alternative per the Rossi feature set), and every chart should state the thresholds and the device/sampling rate.
- Background knowledge, not verified this session: floodlight includes kinematic models (distance, velocity, acceleration) and a metabolic-power model that can be applied to position data such as IDSSE; this would allow a "movement intensity" demonstration from open optical tracking, which must be labelled as optical tracking, not GPS.

### Gaps
- Exact column lists for Catapult OpenField CSV exports and STATSports Sonra summary exports were not obtained from vendor documentation (403 / not public).
- No R package named "statsportsR" was found; no evidence it exists.
- No information retrieved on GPSports, Polar Team Pro or PlayerMaker export formats.
- Definitions/citations for PlayerLoad (Catapult) and metabolic power (Osgnach et al. 2010 / di Prampero) were not retrieved this session; no source to cite.
- The Catapult OpenField Cloud API public documentation URL and endpoint list were not retrieved.
- Licence of databallpy and of the STATSports community pipeline not confirmed.
- FIFA EPTS standard's current version/date is ambiguous (conflicting page dates).

## 6. Injury-risk indicators: published methods, criticisms, and wording

### Takeaway
Workload ratios (ACWR), week-to-week change, monotony and strain are legitimate descriptive load indicators, but the peer-reviewed evidence does not support using them — or current machine-learning models — to predict individual injuries: the ACWR has serious statistical and conceptual criticisms, a cluster-randomised trial of ACWR-guided load management in 482 youth footballers showed no reduction in health problems, and a 2022 systematic review found 98% of 204 sports-injury prediction models at high or unclear risk of bias with none externally validated. The dashboard should present these as load-change indicators for qualified staff, with the caveats visible.

### Cited Findings
Origins and proponents
- Gabbett (BJSM 2016), "The training–injury prevention paradox": athletes accustomed to high training loads tend to have fewer injuries than those on lower loads; introduces the "sweet spot" idea. Secondary sources attribute a lowest-risk ACWR band of 0.8–1.3 to this paper and increased risk above 1.5. — [PMC4789704](https://pmc.ncbi.nlm.nih.gov/articles/PMC4789704)
- Other studies report different bands (e.g. 0.85–1.35 in rugby league, 1.0–1.25 in soccer), and at least one study reported finding no evidence for a 0.8–1.3 "sweet spot". — [PMC7485291](https://pmc.ncbi.nlm.nih.gov/articles/PMC7485291)
- IOC consensus statement (Soligard et al., BJSM 2016;50(17):1030–1041), "How much is too much? (Part 1)": states that emerging evidence indicates poor load management is a major risk factor for injury; defines load broadly (training and competition load, calendar congestion, psychological load, travel); gives guidelines for prescribing and monitoring load. — [Loughborough repository record](https://dspace.lboro.ac.uk/2134/22957)
- Wang et al. (2020) note that the IOC recommended the ACWR for monitoring injury risk. — [Wang et al. abstract](https://read.qxmd.com/read/32125672/analyzing-activity-and-injury-lessons-learned-from-the-acute-chronic-workload-ratio)
- Williams et al. (2017), BJSM letter "Better way to determine the acute:chronic workload ratio?" is the cited source for the EWMA method; later papers describe EWMA as more sensitive than rolling averages. — [ACWR CRAN package references](https://cran.r-project.org/web/packages/ACWR/index.html); [later citing paper, PMC7485291](https://pmc.ncbi.nlm.nih.gov/articles/PMC7485291)
- Gabbett's own later paper (BJSM 2020;54(1), online 2018), "Debunking the myths about training load, injury and performance": says injury likelihood rises on average at ACWR ≥1.5 but that differences between robust and fragile athletes are largely explained by moderators such as age and injury history; a summary lists "1.5 is the magical ratio" as a myth — individuals tolerate loads above and below it. — [BJSM abstract](https://bjsm.bmj.com/content/54/1/58.abstract); [Barça Innovation Hub summary](https://elearning.barcainnovationhub.com/myths-about-training-loads-injuries-and-performance/)

Criticisms
- Mathematical coupling (Lolli et al., BJSM): because the acute week is part of the chronic window, acute and chronic loads are spuriously correlated (r = 0.52 in simulated data for 1,000 athletes); a worked example shows ACWR 1.45 (coupled) vs 1.71 (uncoupled); authors suggest uncoupled ACWRs. — [BJSM 53(15):921 abstract](https://bjsm.bmj.com/content/53/15/921.abstract); [Teesside record](https://research.tees.ac.uk/en/publications/mathematical-coupling-causes-spurious-correlation-within-the-conv-3/)
- Windt & Gabbett (BJSM 2018) responded with "Is it all for naught? What does mathematical coupling mean for acute:chronic workload ratios?", accepting the diagnosis but treating it as a matter of interpretation. — [USQ record](https://research.usq.edu.au/item/q53y9/is-it-all-for-naught-what-does-mathematical-coupling-mean-for-acute-chronic-workload-ratios)
- Wang, Vargas, Stokes, Steele & Shrier (Sports Medicine 2020;50:1243–1254, DOI 10.1007/s40279-020-01280-1): limitations of the ACWR and of how it has been analysed "impact the validity of current recommendations and should discourage its use"; a ratio may not be appropriate to represent change in activity; EWMA has an initial-load problem; inapplicable where athletes taper; proposes causal-inference-based alternatives. — [abstract](https://read.qxmd.com/read/32125672/analyzing-activity-and-injury-lessons-learned-from-the-acute-chronic-workload-ratio)
- Impellizzeri, Tenan, Kempton, Novak & Coutts (IJSPP 2020;15:907–913), "Acute:Chronic Workload Ratio: Conceptual Issues and Fundamental Pitfalls": recommending manipulation of a prognostic factor assumes a causal effect; the ratio was transformed without justification from an additive (Banister-type) model; evidence calls into question the aetiological roles of chronic load and ACWR. — [UTS repository](https://opus.lib.uts.edu.au/citation/handle/10453/141898)
- Impellizzeri, Woodcock, Coutts, Fanchini, McCall & Vigotsky (Sports Medicine 2021;51:581–592), "What Role Do Chronic Workloads Play in the ACWR? Time to Dismiss ACWR and Its Underlying Theory": tested the association by substituting the real chronic load with contrived values; concluded the results disprove the aetiological theory behind the ratio and its components. — [PMC8138569](https://pmc.ncbi.nlm.nih.gov/articles/PMC8138569)
- A counter-view from a practitioner outlet agrees ACWR's predictive value is very limited but argues against discarding it entirely. — [SimpliFaster](https://simplifaster.com/?p=8393)
- Randomised evidence: Dalen-Lorentsen et al. (BJSM 2021;55:108–114; ISRCTN18177140) cluster-randomised 34 elite youth football teams (482 players, both sexes); intervention coaches planned all training by published ACWR load-management principles for a 10-month season. Between-group difference in health-problem prevalence 1.8 percentage points (−4.1 to 7.7; p=0.55); relative risk 1.01 (95% CI 0.91–1.12; p=0.84). Authors: this specific intervention "was not successful in preventing health problems". Primary outcome combined injuries and illnesses. — [Oslo Sports Trauma Research Center summary](https://klokavskade.no/en/about-us/news/does-load-management-using-the-acutechronic-workload-ratio-prevent-health-problems); [NIH Brage record](https://nih.brage.unit.no/nih-xmlui/handle/11250/2720692)
- The same group published "A cherry, ripe for picking: the relationship between the acute-chronic workload ratio and health problems" (title only retrieved). — [NIH Brage record](https://nih.brage.unit.no/nih-xmlui/handle/11250/3123027)

Reviews of predictive validity
- Maupin et al. (2020, Open Access Journal of Sports Medicine) systematic review: relationship between ACWR and injury risk is unclear; issues with the method must be addressed before it is confidently used to mitigate injury risk. — [Bond University record](https://research.bond.edu.au/en/publications/the-relationship-between-acute-chronic-workload-ratios-and-injury/)
- A 2022 systematic review of professional male soccer players reported that session-RPE-based ACWR may be significantly associated with non-contact injury risk but that an ACWR threshold with minimum injury risk could not be obtained (attribution of this URL to the Jiang et al. review should be confirmed). — [PMC9602492](https://pmc.ncbi.nlm.nih.gov/articles/PMC9602492)
- A 2025 systematic review and meta-analysis (22 single-arm cohort studies) concluded ACWR is associated with sports injury risk and may be useful in prevention "but should be used with caution". — [PubMed 41029871](https://pubmed.ncbi.nlm.nih.gov/41029871/)
- A 2026 systematic review (Retos) reported that machine-learning models improved injury prediction but had moderate risk-of-bias concerns, and that predictive accuracy does not necessarily translate into effective injury prevention. — [Retos](https://revistaretos.org/index.php/retos/article/download/118930/84999/517962)
- Bullock et al. (Sports Medicine 2022;52(10):2469–2482), "Just how confident can we be in predicting sports injuries?": 30 studies, 204 models; all studies developed a model and none externally validated one; 98% of models (93% of studies) at high or unclear risk of bias; only 3 studies did an a priori sample-size calculation, 2 reported calibration; no machine-learning study reported code or hyperparameters; authors conclude no model can be recommended for use in practice. — [Keele repository](https://keele-repository.worktribe.com/output/423719/just-how-confident-can-we-be-in-predicting-sports-injuries-a-systematic-review-of-the-methodological-conduct-and-performance-of-existing-musculoskeletal-injury-prediction-models-in-sport)
- Bahr (BJSM 2016;50(13):776–780), "Why screening tests to predict injury do not work—and probably never will": a test must show (1) a strong prospective association, (2) adequate test properties in relevant populations, (3) that targeting high-risk athletes beats giving the intervention to everyone; "there is currently no example of a screening test for sports injuries with adequate test properties"; significant associations help understand causes but are unlikely to predict injury with sufficient accuracy. — [PubMed 27095747](https://pubmed.ncbi.nlm.nih.gov/27095747/)
- West et al. (Int J Sports Med 2021;42(4):300–306), "More than a metric: how training load is used in elite sport for athlete management": load monitoring cannot be reduced to one metric or calculation; injury prediction is extremely difficult given its complex nature, though recognising and measuring known risk factors may help identify periods of elevated risk; no single metric can state the risk of injury or state of preparedness. — [Thieme](https://doi.org//10.1055/a-1268-8791); [preprint](https://core.ac.uk/download/478918752.pdf)

Machine learning from GPS
- Rossi et al. (PLOS ONE 2018;13(7):e0201264), "Effective injury forecasting in soccer with GPS training data and machine learning": 26 professional male players at one Italian club; 23 weeks (1 Jan–31 May 2014); 931 individual training sessions (952 examples); 23 non-contact injuries. Decision tree: injury-class recall 0.80 ± 0.07, precision 0.50 ± 0.11; random forest recall 0.87, precision 0.41; week-by-week simulation detected 9 of 14 injuries from week 6 with precision 0.56 and F1 0.60. ACWR- and monotony-based baselines had maximum precision below about 4–6%. — [PLOS ONE](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0201264)
- Rossi et al. data and code: the data are NOT public (anonymous club, research-only access); transformed non-re-identifiable data offered on request; no code repository URL given. — [PLOS ONE](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0201264)
- Rossi et al. limitations evident in the paper: very few injuries (only 7 in a 30% training split); model needs about 14 weeks of data to stabilise; one club, one season, generalisability untested; training sessions only (no official matches); non-contact injuries only; about half of alerts are false alarms. — [PLOS ONE](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0201264)
- SoccerGuard (2024 preprint) investigates injury risk factors for professional players with machine learning using SoccerMon-type data (details not read). — [arXiv 2411.08901](https://arxiv.org/pdf/2411.08901)

Monotony and strain
- Foster (Med Sci Sports Exerc 1998;30:1164–1168), "Monitoring training in athletes with reference to overtraining syndrome": monotony = daily mean load / standard deviation; strain = load × monotony; these were correlated with illness, alongside a rolling 6-week load average. Session load in the session-RPE method = RPE × duration in minutes (method usually attributed to Foster et al. 2001). — [record](https://lida.sport-iat.de/ta/Record/4001707?lng=en); [Frontiers 2017 review of sRPE](https://www.frontiersin.org/articles/10.3389/fnins.2017.00612/full)
- A 2023 soccer review notes ACWR and monotony have been criticised as injury-risk predictors. — [IPSantarém repository](https://repositorio.ipsantarem.pt/bitstreams/3374ec9e-61c5-4778-9005-be0a25c6a57a/download)

### Inferences
- Even-handed summary for the report: (a) there is a reasonably consistent observed association between rapid load increases and injury at group level, endorsed in the 2016 IOC consensus; (b) the specific ACWR metric is contested on statistical (coupling, ratio artefacts, arbitrary windows) and causal grounds, with some authors calling for it to be dismissed and its originator arguing it remains a useful but not "magic number" guide moderated by individual factors; (c) the one RCT of ACWR-guided management in youth football was null; (d) no injury-prediction model has been externally validated to a standard that reviewers accept.
- Rossi's headline precision of 0.50 means roughly one false alarm per true alert in a 26-player single-club sample; it cannot be reproduced because neither data nor code are public. It should not be implemented or cited in the product as a working predictor.
- No sports-science body appears to prescribe exact wording, but the literature supports wording along these lines (inference, to be reviewed by a qualified practitioner): "Workload change indicator — not an injury prediction or diagnosis. Flags a change in load relative to this player's recent history. Research has not shown that these indicators can predict individual injuries. For review by qualified medical/performance staff alongside wellness, injury history and clinical judgement." Avoid the terms "injury risk score", "probability of injury", "danger zone" and traffic-light colours implying clinical risk.
- Design consequences: show the raw components (acute load, chronic load, week-to-week % change, monotony, strain) next to any ratio; state the calculation variant (rolling coupled / rolling uncoupled / EWMA, window lengths); suppress ratios until enough history exists (EWMA initial-load problem; low chronic loads inflate ratios); never output a probability.

### Gaps
- Full text of the IOC 2016 consensus was not read; its exact ACWR recommendation wording is not quoted here. Whether the IOC has issued an updated load statement since 2016 was not established.
- Hulin et al. (the original cricket/rugby ACWR studies) were not individually retrieved.
- The Impellizzeri et al. JOSPT 2020 papers on "questionable research practices" in the training-load literature were not retrieved (background knowledge only).
- Exact text of West et al.'s section "What we should not use training load for" was truncated in the source retrieved.
- The identity of the 2025 meta-analysis authors and of the 2026 Retos review authors was not confirmed; no 2026 football-specific diagnostic-accuracy review (sensitivity/specificity/AUC of ACWR) was found.
- A monotony threshold of >2.0 appears on a secondary site attributed to Foster; it was not confirmed in a primary source and should not be presented as established.
- No official recommended wording from a sports-science body (e.g. IOC, FIFA medical, BASES) for presenting load indicators in software was found.

### Takeaway

A 2026 MDPI *Data* descriptor offers a lighter session-level male professional dataset (2,375 player-session rows) whose licence still needs confirming. Rossi et al.'s data are not public.

## 8. Alerts: configurable threshold schemes and open implementations

### Takeaway
Open implementations exist in R, not Python: the CRAN `ACWR` package (MIT; EWMA, coupled and uncoupled rolling averages), Jovanović's `athletemonitoring` (MIT per README; rolling acute/chronic windows with user-defined estimators) and `injurytools` (MIT; injury epidemiology, not workload). Their calculations are simple enough to port to Python/pandas; no dedicated maintained Python package was found.

### Cited Findings
- CRAN `ACWR` — "Acute Chronic Workload Ratio Calculation"; computes ACWR by three methods: exponentially weighted moving average (EWMA), rolling average coupled (RAC), rolling average uncoupled (RAU); version 0.1.0 published 2022-03-01; MIT licence; references Williams et al. (2017) for EWMA and Windt & Gabbett (2018) for RAC/RAU; includes a d3.js-based `plot_ACWR`. — [CRAN ACWR](https://cran.r-project.org/web/packages/ACWR/index.html); [README](https://cran.r-project.org/web/packages/ACWR/readme/README.html)
- `athletemonitoring` (Mladen Jovanović) — central `prepare()` function with S3 print/summary/plot; rolling acute and chronic windows set by arguments (README example uses 7 and 42 days); user-supplied rolling estimators (mean, SD, CV); example computes acute–chronic difference (ACD), acute:chronic ratio (ACR) and an effect size ES = ACD / chronic SD; handles missing sessions/days and multiple entries per day. README states MIT; GitHub API reports the licence as unclassified (`NOASSERTION`); last push 2024-05-13; CRAN availability not confirmed. — [mladenjovanovic/athletemonitoring](https://github.com/mladenjovanovic/athletemonitoring)
- CRAN `injurytools` — "A Toolkit for Sports Injury and Illness Data Analysis"; version 2.0.1 published 2026-01-26; MIT + file LICENSE; data preparation, visualisations, descriptive and model-based analyses of injury data (the page does not indicate workload/ACWR functions); GitHub repo last push 2026-01-30. — [CRAN injurytools](https://cran.r-project.org/web/packages/injurytools/index.html); [lzumeta/injurytools](https://github.com/lzumeta/injurytools)
- `athlytics` — R package for endurance (Strava) training data that implements ACWR among other endpoints; not football-specific. — [ecosyste.ms entry](https://awesome.ecosyste.ms/projects/github.com%2Fhzacode%2Fathlytics)
- Threshold schemes documented in the literature retrieved: ACWR bands (0.8–1.3 "sweet spot", >1.5 elevated; with alternative bands 0.85–1.35 and 1.0–1.25 reported, and the 1.5 cut-off described by its originator's group as not a "magical ratio"). — [PMC7485291](https://pmc.ncbi.nlm.nih.gov/articles/PMC7485291); [Barça Innovation Hub summary](https://elearning.barcainnovationhub.com/myths-about-training-loads-injuries-and-performance/)
- Individual-baseline scheme: Jovanović's README example expresses the acute–chronic difference in units of the athlete's own chronic standard deviation (ES = ACD / chronic SD), i.e. an individual z-score-like alert quantity. — [mladenjovanovic/athletemonitoring](https://github.com/mladenjovanovic/athletemonitoring)
- An athlete-monitoring system in real use (PmSys, as used for SoccerMon) derives sRPE, daily/weekly load, ATL, CTL, ACWR, monotony and strain from player reports. — [PMC11139986](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11139986/)
- Individual athletes tolerate loads above and below fixed thresholds; moderators such as age and injury history explain much of the difference. — [BJSM abstract](https://bjsm.bmj.com/content/54/1/58.abstract)

### Inferences
- A configurable alert engine consistent with the evidence would let staff choose, per metric (total distance, HSR, sprint distance, sRPE load, accelerations): (1) rule type — individual-baseline deviation (acute mean minus chronic mean, in chronic SDs), week-to-week % change, ACWR band (with variant RAC/RAU/EWMA and window lengths), monotony/strain level, or absolute cap; (2) threshold values; (3) minimum history required before the rule fires; (4) who is notified. Defaults should be labelled "configurable convention, not a validated risk threshold".
- Individual-baseline (z-score-style) rules avoid two documented ACWR problems (ratio artefacts and coupling) and are easier to explain; offering them as the default and ACWR as an optional view is defensible given section 6.
- Because the R packages are MIT-licensed, their algorithms can be ported to Python with attribution; the EWMA formula should be taken from Williams et al. (2017) directly rather than from memory.
- Alerts should be logged with the rule and parameter values in force at the time, so staff can audit why an alert fired — supporting the brief's requirement that indicators are for qualified staff to review.

### Gaps
- No maintained Python package for ACWR/monotony/strain or athlete-monitoring alerts was found; none can be cited.
- The specific "week-to-week change no more than about 10%" guidance commonly quoted in practice was not sourced this session (background knowledge only) and should not be cited without a reference.
- Whether `athletemonitoring` is currently on CRAN, and its exact licence file, were not confirmed.
- No published evaluation comparing alert schemes (z-score vs ACWR vs % change) on false-alarm rates in football was retrieved.
- Thornton et al. (2019) and similar practitioner frameworks for athlete-monitoring decision rules were not retrieved.
